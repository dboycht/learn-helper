# 学习助理客户端 — 技术文档

> 本文档基于对 `学习助理.exe（PyInstaller onefile, CPython 3.10）` 的反编译重建编写。
> 重建源码：`../client_app_reconstructed.py`（约 3004 行）。

---

## 1. 项目概述

- **程序类型**：Tkinter 桌面客户端 + Playwright 浏览器自动化。
- **用途**：对校内网课/学习平台（`school_id='nuaa'`）自动挂机完成
  视频观看、文档阅读、随堂测验/作业题，问答题由自建后端识别求解。
- **商业模式**：卡密（点数）制。卡密经由发卡平台 `https://www.kufaka.com/shop/BXZ53P9P` 售卖，
  客户端向自建后端 `http://1.13.15.42:8000` 上报卡密与设备指纹，按题数/看课时长扣点数。
- **版本**：`VERSION = '1.0.0'`。

### 1.1 技术栈

| 层 | 选型 |
| --- | --- |
| GUI | Tkinter / ttk / scrolledtext |
| 浏览器自动化 | Playwright（`sync API` + 连接本地浏览器 CDP `http://127.0.0.1:9222`） |
| 浏览器 | Edge（首选）/ Chrome，`--remote-debugging-port=9222` |
| 网络 | `requests`；https 代理被禁用（`urllib.request.getproxies = lambda: {}`） |
| 图片 | PIL（`Image`/`ImageTk`），缺省时退化为 Tk `PhotoImage` |
| 并发 | `ThreadPoolExecutor(max_workers=4)` 并发求解题目 |
| 打包 | PyInstaller onefile，Python 3.10 |

## 3. 数据流

### 3.1 初始化流程（`__main__` → `AppConsole.__init__`）

```
ctypes DLL DPI 感知（shcore→user32 两级回退）
        ↓
keep_computer_awake()            # 防系统睡眠
        ↓
root = tk.Tk(); app = AppConsole(root)
   ├─ 读 %APPDATA%\StudyAssistant\card_key.txt（卡密持久化）
   ├─ create_widgets()            # 构建界面
   ├─ auto_launch_browser_on_start()   # 后台线程拉起沙盒浏览器
   └─ query_points()              # 查询剩余点数 + 版本公告
root.mainloop()
```

### 3.2 刷课主流程（`run_solver_process`，运行于后台线程）

```
校验卡密 & 所选网页 → set_running_ui_state()
  → kill_and_launch_browser() → connect_over_cdp(9222)
  → 锁定目标标签页（按 title 匹配 / 最近页面）; 页面上挂 dialog.accept()
  └─ 循环（每页一迭代）：
      定位章节名 → robust_wait_for_tasks_to_render()（等任务渲染）
      → 定位 cards_frame（knowledge/cards 帧）
      → 逐卡片（Tab 按钮切换）
         ├─ 扫描题目 scan_page_recursively()
         ├─ 若已有分数/已提交（复合 JS 判定）→ 跳过
         ├─ 逐题截图 → 题型识别 → 提取题干(含LaTeX) → 并发 POST /solve
         ├─ 失败题静置4s后单线程重试补刀
         ├─ fill_and_click_smart() 填涂（先判对错再改）
         ├─ 按实际填涂数 POST /solve/checkout 合并扣点（402→强制终止）
         ├─ 自动提交 find_submit_button() + 二次确认(确定/#popok)，失败降级暂存 find_save_button()
         └─ 扫描 div.ans-attach-ct 容器：run_video_task() / run_doc_task()
      → find_next_button() 翻页；弹"还有任务点未完成"→ find_confirmation_bypass_button() 强跳
      → 每 10 页重建标签页释放内存
  收尾：session_history 按题号排序、打印耗时、browser.close()、reset_control_buttons()
```

### 3.3 计数与扣点

| 事件 | 触发逻辑 | 对账口径 |
| --- | --- | --- |
| 做题 | `clicked_ok == 实际填涂成功数` | `deduct_checkout(clicked_ok)`，每道 1 点 |
| 看视频 | `self.accumulated_video_seconds >= 600.0`（每 0.5s +0.5） | `deduct_video_heartbeat()` 扣 1 点 |
| 申诉退点 | `/appeal` 返回 status/points | 后端在审计通过后退回点数 |
| 充值 | `/recharge` 激活码兑换 | 后端入账并返回余额 |

## 5. 后端接口契约

> 约定：所有 `/solve*`、`/appeal` 相关请求携带 `school_id=school_id`；设备身份用 `device_id`。

### 5.1 查询余额
```
GET /points?card_key={key}&device_id={did}&school_id={sid}   timeout=5
200: {"points": int}          # 或 {"detail": "无对应账户"}
```
客户端成功时把卡密写入 `%APPDATA%/StudyAssistant/card_key.txt`。

### 5.2 版本检查
```
GET /check_version?ver={ver}&school_id={sid}&card_key={key}   timeout=5
200: {"notice": str, "force_update": bool, "download_url": str}
force_update=true 时禁用「启动」按钮，提示下载新版本。
```

### 5.3 题目求解（带卡密与设备）
POST /solve   (json)   timeout=150~300
{
  "card_key","image"(base64),"question_type"("choice"|"multi_choice"|"blank"|"essay"),
  "num_blanks","text_hash_source","school_id","device_id"
}
200: {
  "hash_id", "answer_key"?, "text_answers"[]?,
  "remaining_points"?, "cached": bool
}
非 200: {"detail": str}
```

### 5.4 合并扣点
```
POST /solve/checkout  (json)  timeout=25
{"card_key","device_id","school_id","solve_count"}
200: {"remaining_points": int}
402: 点数不足（客户端强制终止）; other: {"detail"}
```

### 5.5 充值
```
POST /recharge (json) timeout=15
{"card_key","recharge_key"}
200: {"remaining_points","msg"}
other: {"detail": str}
```

### 5.6 看课心跳
```
POST /video_heartbeat (json) timeout=10   # 本地累计600秒触发一次
{"card_key","device_id","school_id"}
200: {"remaining_points": int}
402: 点数耗尽（客户端终止）
```

### 5.7 错题申诉
```
POST /appeal (json) timeout=150
{"card_key","hash_id","image"(base64),"user_answer","school_id"}
200: {"status": str, "refund_points"/"remaining_points"?}
```

## 6. 答题识别与填涂规则

### 6.1 题型识别（`detect_question_type_and_inputs`）
- 从 `div.TiMu[data]` 读题型标记：
  - `'0'/'1'/'3'` → 选择类：`'1'` 或多选框存在 → `multi_choice`，否则 `'choice'`；选项数由
    `li.before-after, li[role=radio], li[role=checkbox]` 计数；缺失时兜底 4。
  - `'2'` → 填空：`.blankItemDiv` → `textarea[id^=answer]` → `iframe[id^=ueditor_]` →
    `input[type=text]` 依次回退计数；兜底 1 空。
  - `'4'/'5'/'6'` → 简答 `essay`。
- DOM 无 `div.TiMu` 时按"是否存在选项容器/填空容器"猜测，最终兜底 `essay`。

### 6.2 题干提取（`extract_clean_text_with_latex`）
- JS 遍历文本节点 + 解码 `img.ans-latex-moudle[data]` 中 URL 编码的 LaTeX 图片内容；
- 随后清洗：去题号前缀、去 `（N 分）`、压缩空白。

### 6.3 填涂（`fill_and_click_smart`）
- 答案键预处理：`对/TRUE/T/正确→A`，`错/FALSE/F/错误→B`，其余保留 `A-F`。
- 选项字母推断：`inner_text` 前缀 A–F → 判对/错关键词 → `data` 属性 → 按序号兜底。
- 命中式填涂：先比对 `is_selected` vs `should_select`；全对直接 True；
  否则只点需要改的项；多选题额外取消误选。
- 填空题/简答题走 `FILL_TEXT_SCRIPT`（UEditor 实例、textarea、iframe body、
  input、contenteditable 五路写入）。

## 7. 页面防御与稳定性机制（重建要点）

1. 页面注入 `HACK_SCRIPT` 伪装 `document.hidden=false`、`visibilityState='visible'`，
   清空 `onblur/onfocus`；
2. 视频：`hackVideo(speed)` 静音+倍速；`ended/timeupdate` 置 `__my_video_task_done`；
   播报错 `hackLineSwitch()` 自动换含"公网/线路/推荐/CDN/极速"的线路；
   换线 3 次仍失败 → 重载 iframe；
3. 随堂测验：`hackQuiz()` 随机勾选 1~2 项后 400ms 提交；主循环等测验消失；
4. 文档长页：`autoScrollDocument()` 400px 步进，至 `100.0%` 判定完成；
5. 完成态判定（去重 + 防重复）：容器 class 含 `ans-job-finished/icon_Completed/jobFinish`，
   或页面出现"得分/成绩/我的答案/正确答案/已批阅"等文本、控件全 disabled；
6. 稳定性：每 10 页 `new_page+goto(saved_url)` 重建标签页清内存；分阶段 `check_pause_and_stop()`
   轮询以实现暂停/终止；`SingletonLock` 与 9222 端口探测避免多实例。

## 8. 构建 / 开发备注（供二次开发）

- 运行环境：Python 3.10，依赖 `playwright`、`requests`、`Pillow`、`tkinter`(内置)。
- 沙盒浏览器首次需安装（`playwright` 连接的是**本地已启动**的 Edge/Chrome，不下载浏览器内核）。
- 启动自动化前必须先让用户在沙盒浏览器中登录网课平台并打开做题页，再点本面板「检测/刷新网页」。
- 提交策略：`var_auto_submit`（自动提交=1 / 仅暂存=0）；`var_video_speed` 1.0/1.5/2.0。
- 风险提示：该模式依赖平台 DOM/接口，平台改版会导致选择器失效，需按 §6/§7 规则同步维护。
