# learn-helper 后端对接文档

> 面向**自建后端 / 答题模型服务的实现方**。
> 客户端版本：**2.1.4**　|　本文只描述**本客户端实际使用的接口**；
> 原始 `学习助理.exe` 的完整接口（含卡密、点数、结算）见 `技术文档.md` §5，**本项目已不再使用**。

---

## 0. 一句话概览

客户端只调用**两个**接口：

| 方法 | 路径 | 用途 | 频率 |
| --- | --- | --- | --- |
| `GET` | `/check_version` | 公告 / 强制更新（「测试连接」也用它探活） | 启动时 1 次，可忽略 |
| `POST` | `/solve` | **题目求解（核心）** | 每道题 1 次 |

**没有卡密、没有点数、没有结算、没有充值、没有申诉。** 请求里不含任何账号或计费字段。

---

## 1. 地址与配置

客户端按以下优先级确定后端地址：

1. 同目录 `config.json` 的 `server_url`
2. 环境变量 `LH_SERVER_URL` —— **只在 config.json 没有写 `server_url` 时才生效**
3. 默认 `http://127.0.0.1:8000`

界面「答题设置 → 内部答题 API」里填写的地址保存后即写入 `config.json`。
地址末尾的 `/` 会被客户端去掉，请以 `http://host:port` 形式提供（不要带 `/api` 之类的额外前缀，除非你的服务确实挂在该前缀下）。

`config.json` 结构（供参考，客户端会自动写入）：

```json
{
  "server_url": "http://127.0.0.1:8000",
  "answer": { "mode": "server", "solver_timeout": 240, "workers": 4, "retry": 2 },
  "llm": { "base_url": "https://api.openai.com/v1", "api_key": "sk-...", "model": "gpt-4o" },
  "last_page_url": "https://mooc1.chaoxing.com/...",
  "last_page_title": "学生学习页面"
}
```

> `answer.mode` 决定答题走哪条通道：`server`（本后端）/ `llm`（直连大模型）/ `off`（不答题）。
> **改了必须点「保存」才生效** —— 这是对接时最常踩的坑。

## 2. 公共约定

| 项 | 约定 |
| --- | --- |
| 编码 | 请求与响应均为 UTF-8 JSON |
| `school_id` | 固定 `"nuaa"`（客户端常量） |
| `device_id` | `"DEV-" + md5(str(uuid.getnode())).upper()[:12]`，客户端自动生成，同机稳定 |
| 超时 | `/check_version` 5s；`/solve` 默认 **240s**（界面可配 10~600s） |
| 重试 | `/solve` **仅对网络异常与 5xx 重试**（默认 2 次，退避 1.5s、3s）；4xx 不重试 |
| 并发 | 默认 **4**（界面可配 1~16）。并发只用于网络请求；截图与页面填涂是串行的 |
| 鉴权 | 本项目不带任何鉴权字段。如需鉴权请在自有网络层解决（内网/VPN），或与客户端维护方另行约定 |

## 3. `GET /check_version`

### 请求

```
GET {server_url}/check_version?ver=1.0.3&school_id=nuaa
```

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `ver` | string | 客户端版本号（如 `1.0.3`） |
| `school_id` | string | 固定 `nuaa` |

### 响应 `200`

```json
{
  "notice": "今晚 23:00-24:00 维护，请提前完成任务",
  "force_update": false,
  "download_url": ""
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `notice` | string | 否 | 客户端顶部跑马灯公告 |
| `force_update` | bool | 否 | 为 `true` 时客户端**禁用「启动刷课」**并弹窗提示更新 |
| `download_url` | string | 否 | 预留字段，客户端当前不使用 |

### 其他状态码

客户端不关心，仅把「无法获取后端公告」显示在公告栏。**接口不存在（404）也不会导致客户端异常**。

## 4. `POST /solve` ★ 核心接口

### 请求

```
POST {server_url}/solve
Content-Type: application/json
```

```json
{
  "image": "iVBORw0KGgoAAAANSUhEUgAA...",
  "question_type": "choice",
  "num_blanks": 4,
  "text_hash_source": "中国的首都是哪座城市？ A. 上海 B. 北京 C. 广州 D. 深圳",
  "school_id": "nuaa",
  "device_id": "DEV-9700E71B8EDA"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `image` | string | **题目截图的 base64**（PNG，不含 `data:` 前缀）。典型 5~80 KB |
| `question_type` | string | `choice` 单选 / `multi_choice` 多选 / `blank` 填空 / `essay` 简答 |
| `num_blanks` | int | 见下方「`num_blanks` 语义」 |
| `text_hash_source` | string | 题干文本，见下方「`text_hash_source` 是什么」。**建议直接作为缓存键** |
| `school_id` | string | 固定 `nuaa` |
| `device_id` | string | 设备指纹 |

**`num_blanks` 语义**（同一个字段在不同题型下含义不同，请按题型解释）：

| 题型 | 含义 | 客户端取不到时的兜底 |
| --- | --- | --- |
| `choice` / `multi_choice` | **选项个数** | `4` |
| `blank` | **填空个数**（即 `text_answers` 应有几个元素） | `1` |
| `essay` | 固定 `1` | `1` |

所以 **`num_blanks` 不会为 0**；填空题请务必按它返回等长的 `text_answers`。

**`text_hash_source` 是什么**：客户端从**整个题目容器**里递归取所有文本节点拼接而成
（`extract_clean_text_with_latex`）—— 因此**包含题干与各选项的文字**；
题目里的 LaTeX 图片会被解码成对应的 LaTeX 文本一并拼入；
随后去掉题号前缀（如 `1.`）、去掉「（N 分）」、压缩空白。

> 字段名沿用原程序命名，**它承载的是题干文本，不是哈希值**。
> 同一道题在不同学生机器上应得到几乎相同的字符串，适合做缓存键；建议再叠加图片哈希以防误命中。

### 响应 `200`

```json
{
  "hash_id": "q-8f3a1c",
  "answer_key": "B",
  "cached": false
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `answer_key` | string | 选择/多选题**必填** | 选项字母组合，大写，如 `"A"`、`"ACD"`；多选请按字母升序 |
| `text_answers` | string[] | 填空/简答题**必填** | 按空的顺序排列；简答放一个元素 |
| `hash_id` | string | 否 | 题目标识。客户端**仅记录到日志**（原程序用它做错题申诉，本项目无此功能） |
| `cached` | bool | 否 | 后端缓存命中标记；客户端会记为「后端缓存命中」并打日志 |

**`answer_key` 与 `text_answers` 至少给一个**；也可以都给（客户端按题型取用）。

### 错误响应

非 200 一律返回可读 JSON，客户端会记录并（仅 5xx）重试：

```json
{ "detail": "模型推理超时" }
```

| 状态码 | 客户端行为 |
| --- | --- |
| `401` / `403` | **立即失败，不重试**。日志 `后端拒绝访问（HTTP 401）：<detail>` |
| `404` | **立即失败，不重试**。日志 `后端没有该接口（HTTP 404）` |
| 其他 `4xx`（如 422） | **立即失败，不重试**。日志 `请求被后端拒绝（HTTP 422）：<detail>` |
| `5xx` | 按配置重试（默认 2 次，退避 1.5s、3s） |
| 网络异常 / 超时 | 同上按配置重试 |

> 4xx 一定是"重试也不会变好"的错误（路由写错、字段不合规范、鉴权失败），
> 客户端**不会**浪费你的时间反复重试；请把这类错误修好再测。

**单题失败不会中断刷课**：客户端记录 `[题 N] 求解失败: ...` 后继续下一题，其余题照常填涂。

## 5. 响应解析规则（请按此实现，避免返工）

客户端对返回做**尽力鲁棒**的归一化，规则如下：

1. `answer_key`：只保留 `[A-Fa-f]` 字符并转大写（`"a c"` → `"AC"`）。
2. 若 `answer_key` 非空 → 题型按**字母个数**判定：1 个 = `choice`，多个 = `multi_choice`。
   - ⚠️ 单选题请**只返回一个字母**，否则会被当作多选题处理、只勾选一个可能判错。
3. 否则若 `text_answers` 非空 → 按题型走 `blank` / `essay`，数组元素**按顺序填入各空**，
   空字符串会被丢弃。
4. 两者都为空 → 客户端记 `⚠ 接口通了，但没返回可用的答案`。

**建议后端做兜底**：模型输出不稳定时请自行解析成规范 JSON 再返回，
不要让客户端去猜自然语言（客户端只做字母过滤，不做语义解析）。

## 6. 参考实现（FastAPI 最小可用）

```python
# pip install fastapi uvicorn pillow
import base64, hashlib, io, json
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()
CACHE: dict[str, dict] = {}

class SolveReq(BaseModel):
    image: str
    question_type: str          # choice | multi_choice | blank | essay
    num_blanks: int = 0
    text_hash_source: str = ""
    school_id: str = "nuaa"
    device_id: str = ""

@app.get("/check_version")
def check_version(ver: str = "", school_id: str = ""):
    return {"notice": "服务正常", "force_update": False, "download_url": ""}

@app.post("/solve")
def solve(req: SolveReq):
    key = hashlib.md5(
        (req.text_hash_source + req.image[:200]).encode("utf-8")
    ).hexdigest()
    if key in CACHE:
        return {**CACHE[key], "cached": True}

    img = base64.b64decode(req.image)          # 这就是题目截图 PNG 字节

    # ---- 在这里接你自己的模型 ----
    # 例：把 img 与 req.text_hash_source 交给视觉模型，拿回结构化答案
    ans = my_model_solve(img, req.question_type, req.num_blanks, req.text_hash_source)

    resp = {
        "hash_id": key[:12],
        "answer_key": ans.get("answer_key", ""),
        "text_answers": ans.get("text_answers", []),
    }
    CACHE[key] = resp
    return {**resp, "cached": False}

# uvicorn main:app --host 0.0.0.0 --port 8000
```

要点：
- **务必给模型设超时**（建议 60~120s）。客户端超时是 240s，后端若卡住会拖满整个批次。
- **建议按 `text_hash_source` 做缓存** —— 同一道题会被多个学生遇到，且客户端重试时会重复请求。
- 服务要能承受**默认 4 路并发**（可按需提高，客户端可配到 16）。

## 7. 另一条通道：自配大模型（不经自建后端）

若使用方直接配置 OpenAI 兼容接口（`answer.mode = "llm"`），客户端会这样调用：

```
POST {base_url}/chat/completions
Authorization: Bearer {api_key}
```

```json
{
  "model": "deepseek-flash",
  "messages": [{
    "role": "user",
    "content": [
      { "type": "text", "text": "<答题提示词：要求只输出 JSON>" },
      { "type": "image_url",
        "image_url": { "url": "data:image/png;base64,<题目截图>", "detail": "high" } }
    ]
  }],
  "temperature": 0.1
}
```

- 期望模型返回 `{"question_type": "...", "answer_key": "...", "text_answers": [...]}`，
  客户端用正则抽取其中第一个 `{...}` 解析；抽不到时退化为"抽 A-F 字母 / 整段当文本"。
- **模型必须支持图片输入**；`detail: "high"` 用于保留原分辨率（题目截图字小且密）。
- 这一通道**不经过自建后端**，两条通道互不影响。

## 8. 对接调试：用客户端内置自检

打开「答题设置」，单个页面里用 **[测试连接]** 验证当前答题方式选中的通道，
结果写在窗口底部状态行，同时**逐行写入** `logs/learn_helper.log`（可事后追溯）。

> ⚠️ **「测试图片」按钮在本版客户端里已不再提供**（2.1.1 起界面重构为原生 UI 时未迁移）。
> 后端仍保留 `POST /api/control {"action":"self_test"}` 这个动作，但目前没有任何界面入口调用它；
> 要验证"模型能不能识图"，请直接按 §11 的 `curl` 示例发一张真实题图。
> （另外「两个页签」也早就没有了：现在是单页 + 三张答题方式卡片。）

| 按钮 | 行为 |
| --- | --- |
| **测试连接** | 按当前答题方式：`server` 走 `GET /check_version`（回显后端公告与设备指纹）；`llm` 发一句纯文本探活（**不能证明模型能识图**） |

自检用的 3 道内置题与**期望答案**：

| # | 题型 | 题目 | 期望答案 |
| --- | --- | --- | --- |
| 1 | `choice` | 中国的首都是哪座城市？A.上海 B.北京 C.广州 D.深圳 | `B` |
| 2 | `multi_choice` | 下列哪些属于哺乳动物？（多选）A.鲸鱼 B.鲨鱼 C.蝙蝠 D.鳄鱼 | `AC` |
| 3 | `blank` | 填空题：一年有 \_\_\_\_ 个月。 | `12` |

结果三态区分，便于定位问题：

| 标记 | 含义 | 说明 |
| --- | --- | --- |
| `✓` | 识别正确 | 接口通且答案与期望一致 |
| `⚠` | 接口通但答案不符 / 为空 | 网络与协议没问题，是**模型识图或作答**的问题 |
| `✗` | 请求失败 | 地址不可达、协议不符、超时或 4xx/5xx |

> **两个测试按钮都用输入框里当前填的值，不需要先保存**；若与已保存值不同，结果里会提醒你保存。

## 9. 与原始 `学习助理.exe` 的接口差异（**重要**）

如果你手上已有原程序的后端，请注意客户端**不再发送**以下字段 —— 若后端做了强制校验会直接 422：

| 原程序接口 / 字段 | 本项目状态 |
| --- | --- |
| `GET /points`（查点数余额） | **已删除，不再调用** |
| `POST /solve/checkout`（合并扣点） | **已删除，不再调用** |
| `POST /video_heartbeat`（看课心跳扣点） | **已删除，不再调用** |
| `GET /check_version` 的 `card_key` 参数 | **不再发送** |
| `POST /solve` 的 `card_key` 字段 | **不再发送** |
| `POST /solve` 响应里的 `remaining_points` | **不再解析** |
| `POST /recharge`（充值） | 从未移植 |
| `POST /appeal`（错题申诉退点） | 从未移植 |

**处理建议**：把 `/solve` 的 `card_key` 改为可选（或直接删掉校验），
其余计费接口保留不影响使用，只是永远不会被调用。

## 10. 常见问题速查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 「测试连接」成功，但刷课时每题都失败 | `answer.mode` 不是 `server`，或保存前测试的是另一个地址 | 切到正确通道并**点保存** |
| `✗ 3 题全部请求失败` | 地址不通 / 端口未监听 / 路径带了额外前缀 | 用 `curl` 直接打 `/check_version` 验证 |
| `✗ ... HTTP 422` | 后端仍在强制校验 `card_key` 等已删除字段 | 见 §9，把校验改为可选 |
| `⚠ 接口正常但答案不符` | 模型识图不准 / 提示词不同 / 返回的不是规范 JSON | 用同一张测试图直接调你的模型对比 |
| `⚠ 接口通了，但没返回可用的答案` | 响应字段名不对（如写成 `answer` 而非 `answer_key`） | 核对 §4 字段名 |
| 答题很慢 | 单题耗时高 + 并发低 | 提高后端吞吐，或在界面把「并发求解」调到 8~16 |
| 想复现客户端到底发了什么 | — | 看 `logs/learn_helper.log`，每次 `/solve` 都有 `[内部答题] POST ... type=... num=... img=...B` |

## 11. 最小自测（curl）

```bash
# 1) 探活
curl "http://127.0.0.1:8000/check_version?ver=1.0.3&school_id=nuaa"

# 2) 求解（用一张真实的题目截图）
IMG=$(base64 -w0 question.png)
curl -X POST http://127.0.0.1:8000/solve \
  -H "Content-Type: application/json" \
  -d "{\"image\":\"$IMG\",\"question_type\":\"choice\",\"num_blanks\":4,
       \"text_hash_source\":\"中国的首都是哪座城市？\",\"school_id\":\"nuaa\",
       \"device_id\":\"DEV-TEST00000000\"}"
```

期望响应：`{"answer_key":"B", ...}`。
不确定发什么图，就**随便截一张真实题图**（题目截图字小且密时建议 `detail: "high"`），
或用上面这段 `curl` 换成你自己的图片 base64 先打通链路。
